## Abstract

В работе оценивается применимость обучаемого фронтенда сопоставления точек в задаче визуальной одометрии по надирной аэросъёмке. На датасете ALTO (Огайо, кадры 500×500 px, шаг между кадрами около 2.8 м, высота над землёй 195 м) построен монокулярный пайплайн и сопоставлены три фронтенда: классические дескрипторы (SIFT + BFMatcher), оптический поток (ORB + Lucas–Kanade) и обучаемая связка SuperPoint + LightGlue. Из опорной публикации заимствована её ключевая метрика — AUC ошибки относительной позы при порогах 5°, 10° и 20° — и воспроизведена на рассматриваемом домене при едином для всех подходов оценщике позы; корректность реализации подтверждена на синтетических данных с известным решением. Дополнительно решена задача, отсутствующая в исходной публикации: восстановление постоянного разворота между системой координат кватерниона телеметрии и системой координат камеры, без которого метрика измеряет соглашение об осях, а не качество метода.

Получены четыре результата. Во-первых, расхождение с опубликованными значениями зависит от порога: при мягком пороге воспроизведение близко к опубликованному (AUC@20 = {{AUC20_SP}} против 84.10 у SuperPoint + LightGlue на MegaDepth-1500), тогда как при строгом разрыв велик ({{AUC5_SP}} против 58.80), поскольку распределение ошибки направления трансляции сосредоточено около {{MEDT_SP}}° — ниже порога 5°, но недостаточно далеко от него. Во-вторых, суммарная метрика max(e_R, e_t) на этом домене тождественно совпала со своей трансляционной компонентой: ошибка вращения оказалась меньше ошибки направления на каждой без исключения паре, поэтому информативно лишь раздельное вычисление AUC_R и AUC_t, которое к тому же меняет ранг подходов на противоположный. В-третьих, по покадровому качеству соответствий обучаемый фронтенд оказался лучшим, на более трудном сплите с отрывом, превышающим уровень шума измерения на порядок, однако это преимущество не переносится на точность траектории, где он уступает классическим (ATE 97.4 м против 42.3 м): определяющим звеном системы является геометрический решатель, а не фронтенд. В-четвёртых, измерена чувствительность метрики к протоколу: инлайер-порог в диапазоне 0.25–3 px на результат практически не влияет, тип робастного оценщика даёт до {{PROTO5_SPREAD}} пункта AUC@5, интерполяционное увеличение разрешения не даёт ничего.

## 1. Mathematical Preliminaries

### 1.1. Постановка и модель камеры

Кадры ALTO получены ресайзом и кропом из исходных 1600×1200, поэтому истинная матрица камеры неизвестна и восстанавливается по данным. Для строго надирной камеры над плоской подстилающей поверхностью масштаб на местности (GSD, ground sample distance) связан с фокусным расстоянием и высотой над землёй соотношением

```
GSD = AGL / f          [м/пиксель]
```

Отсюда следует существенное для всей работы обстоятельство: f и AGL по плоской надирной сцене неразделимы, в наблюдения они входят только через отношение. Принято f = 324.07 px из геометрии кропа, что даёт AGL = 194.8 м; любое другое согласованное разбиение приводит к тем же угловым метрикам.

Матрица внутренних параметров:

```
K = [ 324.07     0     250.0 ]
    [    0    324.07   250.0 ]
    [    0       0       1.0 ]
```

### 1.2. Относительная поза из соответствий

Пусть точка сцены наблюдается в двух кадрах. В конвенции OpenCV (x вправо, y вниз, z вперёд) точки камер связаны как

```
p1 = R p0 + t
```

Эссенциальная матрица E = [t]× R связывает нормированные координаты уравнением p1ᵀ E p0 = 0. Решение пятиточечного алгоритма внутри RANSAC даёт E, из которой разложением и проверкой положительности глубины (cheirality) извлекаются R и t. Длина t принципиально не определена: монокулярная постановка даёт направление движения, но не его величину. Именно поэтому метрика опорной публикации построена на углах, что делает её применимой к монокулярному случаю без внешнего масштаба.

### 1.3. Вырождение на плоскости

Для сцены, лежащей в плоскости на расстоянии d с нормалью n (в системе первого кадра), истинное преобразование между изображениями — гомография

```
H = R + t nᵀ / d
```

Отсюда следуют два обстоятельства, определяющие поведение метрики на рассматриваемом домене. Во-первых, при строго планарной сцене эссенциальная матрица определяется неоднозначно, а при почти планарной — плохо обусловлена. Во-вторых, слагаемое t nᵀ / d содержит антисимметричную часть

```
(t_x n_y − t_y n_x) / (2d)
```

то есть сдвиговую деформацию. Модель подобия (сдвиг, поворот, масштаб) сдвиговой компоненты не содержит, вследствие чего половина её величины интерпретируется оценщиком как поворот. На ALTO этот эффект измерен: −0.151°/шаг на сплите Train, что за 28.5 км даёт накопленный ложный разворот 162° при истинном изменении курса 4.7°. Прогноз смещения только из эталонной ориентации воспроизводит 56 % наблюдаемой величины при наклоне регрессии 1.03.

### 1.4. Метрика: AUC ошибки относительной позы

Опорная публикация оценивает качество сопоставления через точность относительной позы, восстановленной из соответствий с помощью RANSAC. Ошибка позы определяется как максимум двух угловых ошибок:

```
e_R = arccos( ( tr(R_estᵀ R_gt) − 1 ) / 2 )
e_t = arccos( <t_est, t_gt> / (|t_est| · |t_gt|) )
e   = max(e_R, e_t)                                 [градусы]
```

Знак трансляции из эссенциальной матрицы определён с точностью до направления, поэтому каноническая реализация сворачивает e_t ← min(e_t, 180° − e_t).

Пусть F(x) — доля пар с ошибкой не выше x. Тогда

```
AUC@X = (1/X) ∫₀ˣ F(x') dx'  ∈ [0, 1]
```

Содержательно это средняя по порогам доля успешно оценённых пар. Равномерно распределённая на [0°, 20°] ошибка даёт AUC@20 = 0.5, AUC@10 = 0.25, AUC@5 = 0.125; эти значения использованы как аналитический тест реализации.

Опорная публикация задаёт протокол явно: эссенциальная матрица оценивается LO-RANSAC с инлайер-порогом 0.5 пикселя, кадры приводятся к 832×832. Такая полнота нетипична — большинство работ ограничивается ссылкой на протокол SuperGlue/LoFTR, не выписывая ни формулу площади, ни правило обработки отказов оценщика. Так, в публикации по DALGlue раздел с описанием метрик смешивает оценку гомографий и оценку поз, а разрешение кадров не указано.

Полнота описания протокола существенна: как показано в §3.5, часть разброса опубликованных значений объясняется именно им. В настоящей работе воспроизводится каноническая реализация SuperGlue, на которую ссылаются обе публикации; протокол опорной публикации соблюдается в той части, в которой он специфицирован, а расхождения фиксируются явно (см. Discussions).

### 1.5. Истинная относительная поза из телеметрии

В MegaDepth эталонные позы получены SfM-реконструкцией и выражены непосредственно в системе координат камеры. ALTO предоставляет позицию в UTM 17N и кватернион относительно ECEF, при этом система координат кватерниона не документирована: конвенция осей определена производителем, а камера установлена под некоторым углом к продольной оси носителя.

Пусть точка мира в локальном ENU связана с точкой в системе OpenCV как

```
p_enu = Q_i · P · p_cv + c_i
```

где Q_i — матрица кватерниона, c_i — центр камеры, P — постоянный (одинаковый для всех кадров) разворот. Тогда относительная поза в конвенции cv2.recoverPose:

```
R_gt = Pᵀ Q1ᵀ Q0 P
t_gt = Pᵀ Q1ᵀ (c0 − c1)
```

Отметим, что P не сокращается, а входит сопряжением. Сопряжение сохраняет угол поворота, но меняет его ось, поэтому e_R искажается умеренно; направление трансляции поворачивается на угол крепления целиком, и e_t возрастает ровно на эту величину. Синтетическая проверка показывает, что неучтённый разворот крепления в 17° обнуляет AUC@5 и AUC@10.

Разворот P оценивается следующим образом. Перебираются 24 матрицы вида «перестановка осей и знаки»; отбираются те, при которых ось z камеры направлена вниз. Для каждой предсказывается направление сдвига сцены в кадре — у почти надирной камеры оно сонаправлено с (t_x, t_y). Предсказание сравнивается с измеренным сдвигом, полученным моделью 2D-подобия по точкам ORB. Остаточный поворот вокруг оптической оси устраняется непрерывной поправкой ψ₀. Измеритель сдвига не входит в число сравниваемых фронтендов, а оценщик позы в калибровке не участвует, поэтому процедура не замкнута на оцениваемый пайплайн.

Полученные значения: ψ₀ = {{PSI0}}°, согласованность калибровки {{RESULTANT}} при единице как идеальном совпадении предсказанного и измеренного направлений на всех парах. Малость ψ₀ означает, что оси крепления камеры с точностью до градуса совпадают с осями телеметрии; тем не менее шаг калибровки необходим, поскольку априорных оснований для такого совпадения нет, а цена ошибки, как показано выше, велика.

### 2.3. Сравниваемые подходы

Далее используется принятое в литературе по SLAM разделение системы на *фронтенд* (front-end) и *бэкенд* (back-end) [18]. Фронтенд обрабатывает изображения и выдаёт соответствия между кадрами: детектирование точек, описание окрестностей, сопоставление. Бэкенд оперирует полученными соответствиями и решает геометрическую задачу — оценку относительной позы, а в полных системах также оптимизацию траектории и замыкание циклов. Предметом сравнения являются фронтенды при фиксированном бэкенде.

| | подход | фронтенд | параметры |
|---|---|---|---|
| (a) | классические дескрипторы | SIFT + BFMatcher | 2000 точек, ratio 0.8, взаимная проверка |
| (b) | оптический поток | ORB + пирамидальный Lucas–Kanade | окно 21, 4 уровня, forward-backward порог 1 px |
| (c) | обучаемый фронтенд | SuperPoint + LightGlue | 2048 точек, порог детекции 5·10⁻⁴, fp32 |

Оценщик позы у всех трёх одинаков: эссенциальная матрица и `cv2.recoverPose`. Это соответствует постановке опорной публикации, в которой сравниваются фронтенды, а не геометрические решатели.

Параметры решателя взяты из опорной публикации: инлайер-порог 0.5 пикселя, доверие 0.9999. LO-RANSAC, применяемый авторами, в OpenCV отсутствует; ближайший доступный аналог — `USAC_ACCURATE`, то есть RANSAC с локальной оптимизацией на инлайерах. Величина обусловленного этим расхождения измерена в §3.5.

Замечание о доступности: пакет kornia не содержит экстрактора SuperPoint (проверено в версии 0.8.3), в нём присутствуют лишь матчер LightGlue и детектор DISK. При недоступности основного пути установки (пакет cvg/LightGlue) запасным вариантом является DISK + LightGlue, который в отчёте следует называть своим именем. В настоящем прогоне использован именно SuperPoint + LightGlue, что зафиксировано в журнале выполнения.

### 2.4. Протокол измерения

Из сплита {{SPLIT}} равномерно выбираются {{NPAIRS}} пар кадров (i, i + {{STRIDE}}), медианная база {{BASE_M}} м, отношение база/глубина {{BASE_DEPTH}}. Для каждой пары вычисляются e_R и e_t, затем по всей выборке — AUC при порогах 5°, 10°, 20°. Отказ оценщика кодируется ошибкой 180°, то есть учитывается как проваленная пара, а не исключается. Главное наблюдение — совпадение суммарной метрики с её трансляционной компонентой: AUC@5 = AUC_t@5, AUC@10 = AUC_t@10 и AUC@20 = AUC_t@20 для всех трёх подходов с точностью до второго знака. Это означает, что неравенство e_R < e_t выполняется на каждой паре выборки без исключения, и ошибка вращения в формировании метрики не участвует вовсе.

Второе наблюдение — общий для всех подходов уровень ошибки направления: медианы e_t равны 3.53°, 3.64° и {{MEDT_SP}}° при том, что число соответствий различается более чем в четыре раза. Разброс в 3 % при столь разных фронтендах указывает, что величина определяется не качеством сопоставления.

Третье — обратное соотношение между долей инлайеров и точностью позы. У обучаемого фронтенда наименьшая доля инлайеров и наименьшая эпиполярная точность ({{PREC_SP}}), но наилучшая AUC; у ORB + Lucas–Kanade сочетание противоположное. Это независимо подтверждает вывод первой части работы о непригодности доли инлайеров как индикатора качества.

## 4. Discussions

### 4.1. Положение обучаемого фронтенда по двум группам метрик

По метрике опорной публикации обучаемый фронтенд оказался лучшим из трёх. На сплите Val его преимущество над SIFT составляет менее одной десятой пункта AUC@5 и лежит ниже уровня шума измерения (§4.3), однако на сплите Train отрыв достигает 2.6 пункта над ORB + Lucas–Kanade и 5.7 пункта над SIFT, а по AUC@20 — 1.3 и 11.0 пункта соответственно. Преимущество устойчиво и при изменении разрешения: обучаемый фронтенд единственный, чьи значения не деградируют при интерполяционном увеличении кадра.

По точности траектории он при этом последний из трёх, а по вычислительной стоимости уступает наиболее быстрому варианту в пять раз (в настоящем прогоне 101 мс против 20 мс на пару) и требует 577 МБ видеопамяти.

Противоречие разрешается тем, что две метрики характеризуют разные звенья системы. AUC ошибки позы вычисляется покадрово при фиксированном бэкенде и отражает качество соответствий. ATE накапливает ошибку вдоль траектории и определяется главным образом свойствами геометрического решателя и политики масштаба: в первой части работы разброс ATE по бэкендам составлял 157 % против 5.6 % по фронтендам. Следовательно улучшение фронтенда, измеримое метрикой публикации, на этом домене не является определяющим для конечной задачи навигации.

Механизм отставания обучаемого детектора по устойчивости точек при этом сохраняется и виден в §3.6: корреляция повторяемости SuperPoint с локальной текстурой равна 0.481, вдвое выше, чем у ORB (0.251). Детектор, обученный на городских и предметных сценах, ориентирован на углы объектов и структурные пересечения, тогда как надирная съёмка равнины даёт поля, лесополосы и дороги, где такие структуры сосредоточены в небольшой части кадра. Точки концентрируются в текстурных областях, что снижает обусловленность оценки позы. Тем не менее обучаемый матчер этот недостаток компенсирует: при вчетверо меньшем числе соответствий, чем у Lucas–Kanade, и наименьшей доле инлайеров он даёт наилучшую точность направления трансляции.

Практический вывод: применение обучаемого фронтенда на данном домене оправдано, если целевой величиной является покадровая точность относительной позы — например, для геопривязки или замыкания циклов, — и не оправдано, если целевой величиной является точность накопленной траектории, где вычислительные ресурсы разумнее вложить в геометрический решатель.

### 4.2. Природа расхождения с опубликованными значениями

Расхождение складывается из двух составляющих, которые следует рассматривать раздельно.

**Протокол.** Измерение (§3.5) показало, что вклад этой составляющей ограничен: инлайер-порог влияния не оказывает, интерполяционное увеличение разрешения не оказывает, значим лишь тип робастного оценщика, дающий до {{PROTO5_SPREAD}} пункта AUC@5. Исходная гипотеза о том, что протокол объясняет существенную часть тридцатипунктового разрыва, не подтвердилась и отвергается. Существенным остаётся лишь тот аспект разрешения, который масштабированием не воспроизводится: кадр 500×500 несёт меньше информации, чем 832×832, и восполнить это интерполяцией невозможно.

**Свойства домена.** Основная часть расхождения объясняется геометрией сцены и точностью эталона.

*Параллакс.* В MegaDepth пары формируются из разных снимков одного объекта, смещение камеры сравнимо с расстоянием до сцены. Здесь при рабочей базе отношение база/глубина равно {{BASE_DEPTH}}, а при базе в один кадр — 0.01. Развёртка §3.3 показывает, что ниже отношения порядка 0.03 задача становится неразрешимой: обе компоненты ошибки достигают 180°. При рабочей базе параллакса достаточно, и наблюдаемая ошибка направления составляет единицы градусов.

*Планарность.* Надирная съёмка равнины близка к идеальной плоскости, на которой эссенциальная матрица вырождается. Формально пятиточечный алгоритм выдаёт решение всегда, однако обусловленность задачи низка, и робастный оценщик выбирает решение, согласованное с данными, но не обязательно верное. Этот вывод получает независимое подтверждение в литературе того же года: работа Planar-SfM (ICPR 2026) исходит из той же посылки и предлагает использовать плоскость как источник геометрических ограничений, оценивая относительную позу разложением гомографии. Результат первой части настоящей работы совпадает с этим по существу и получен независимо: на сплите Train гомография давала ATE 1197–1541 м против 5260–7326 м у эссенциальной матрицы. Поскольку метрика опорной публикации построена именно на эссенциальной матрице, на таком домене она систематически занижена одновременно для всех сравниваемых методов.

*Точность эталона.* Эталонные позы MegaDepth получены bundle adjustment, здесь — из GNSS/INS, дополненных калибровкой разворота крепления, остаточная погрешность которой на синтетике составила 0.46°. Наблюдение §3.2 — совпадение медиан e_t у трёх подходов с точностью до 3 % при четырёхкратном различии числа соответствий — указывает, что уровень порядка {{MEDT_SP}}° определяется не фронтендом. Наиболее вероятные источники: точность телеметрии, остаточная погрешность калибровки и систематическое смещение, вносимое квазипланарностью. Разделение этих вкладов требует эталона иного происхождения и вынесено в направления развития.

**Роль суммарной метрики.** Совпадение AUC с AUC_t на каждой паре (§3.2) означает, что на рассматриваемом домене метрика e = max(e_R, e_t) не содержит информации о вращении. При этом ранг подходов по вращению отличается от ранга по трансляции: наилучшую AUC_R даёт ORB + Lucas–Kanade, наилучшую AUC_t — обучаемый фронтенд. Суммарная метрика этот переворот скрывает полностью, что и составляет основное методическое возражение против её применения вне доменов с богатым параллаксом.

### 4.3. Ограничения воспроизведения

Определения в публикациях часто неполны, поэтому допущения перечислены явно:

- площадь под кривой вычисляется по канонической реализации SuperGlue (кусочно-линейная интерполяция эмпирической функции распределения, нормировка на порог); в опорной публикации формула не выписана;
- отказ оценщика кодируется ошибкой 180°, пара не исключается; поведение при отказе в публикации не описано;
- e_t сворачивается как min(e_t, 180° − e_t) — соглашение той же реализации;
- эталонные позы берутся из телеметрии, а не из SfM;
- пары с базой менее 1 м исключаются как вырожденные;
- аналог MMA вычисляется по эпиполярной невязке, а не по эталонной гомографии: соответствие может лежать на эпиполярной линии и всё же быть ошибочным, поэтому приведённая величина является верхней оценкой точности сопоставления;
- LO-RANSAC из PoseLib, применяемый опорной публикацией, в OpenCV отсутствует; использован `USAC_ACCURATE`, величина обусловленного этим расхождения измерена в §3.5;
- разрешение исходных кадров фиксировано природой данных (500×500), поэтому сопоставление с протоколом 832×832 выполнено интерполяционным увеличением, которое информации не добавляет и служит только для изоляции фактора масштаба.

Отдельно оценён уровень шума измерения. Подход (a) на разрешении 500 px измерен дважды на разных подвыборках пар — в §3.2 и §3.5 — и дал 29.14 и 29.85 AUC@5. Различие в 0.71 пункта задаёт порог значимости: различия меньшего порядка, включая преимущество обучаемого фронтенда на сплите Val, интерпретации не подлежат, тогда как отрыв на сплите Train превышает этот порог многократно. Все прогоны выполнены с единственным начальным состоянием генератора случайных чисел; систематическая оценка разброса вынесена в направления развития.

Следует также отметить несогласованность опубликованных значений между собой. Помимо межпубликационного разброса из §3.5, в работе по DALGlue значения AUC для предлагаемого метода различаются между аннотацией (57.01 / 73.00 / 84.11) и разделом абляции (57.42 / 73.57 / 84.11); первый набор, по-видимому, получен пересчётом заявленного относительного прироста: 47.83 × 1.191 = 56.97.

### 4.4. Границы применимости метрики

AUC ошибки позы вычисляется покадрово и не накапливает дрейф, вследствие чего не отвечает на вопрос о качестве итоговой траектории. В первой части работы ранг методов менялся между сплитами (на Val точнее эссенциальная матрица, на Train — гомография), а разброс по бэкендам достигал 157 % против 5.6 % по фронтендам. Метрика опорной публикации этого измерить не может по построению, поскольку фиксирует геометрический решатель. Настоящая работа даёт прямое подтверждение: ранг подходов по AUC противоположен рангу по ATE. Обе метрики необходимы совместно — первая характеризует качество соответствий, вторая пригодность системы к навигации.

## 5. Conclusion & Future Work

**Выводы.**

1. Метрика AUC ошибки относительной позы воспроизведена и валидирована на синтетике с известным ответом; реализация даёт аналитически ожидаемые значения.
2. Для датасета с телеметрией вместо SfM-эталона обязательным шагом является калибровка постоянного разворота между системой кватерниона и системой камеры. Без неё метрика измеряет соглашение об осях: неучтённый разворот в 17° обнуляет AUC@5. Для ALTO этот разворот оказался близок к нулю ({{PSI0}}°), однако установлено это измерением, а не предположением.
3. На рассматриваемом домене суммарная метрика max(e_R, e_t) тождественно совпадает со своей трансляционной компонентой и не содержит информации о вращении. Поскольку ранг подходов по вращению и по трансляции различен, метрику следует применять в раздельной форме AUC_R и AUC_t.
4. Расхождение с опубликованными значениями зависит от порога: при 20° оно составляет менее двух пунктов, при 5° — около тридцати. Источником является не отказ метода, а систематическое смещение ошибки направления трансляции на уровне {{MEDT_SP}}°, одинаковое для всех трёх подходов и потому относящееся к свойствам данных, а не фронтендов.
5. Гипотеза о существенном вкладе протокола в это расхождение проверена и отвергнута: инлайер-порог влияния не оказывает, интерполяционное увеличение разрешения не оказывает, значим лишь тип робастного оценщика ({{PROTO5_SPREAD}} пункта AUC@5).
6. По метрике опорной публикации обучаемый фронтенд SuperPoint + LightGlue является лучшим из трёх, на более трудном сплите с отрывом, превышающим уровень шума измерения на порядок. По точности накопленной траектории он последний. Противоречие объясняется тем, что определяющим звеном системы на этом домене является геометрический решатель, а не фронтенд.

**Направления развития.**

- Оценщик позы, учитывающий планарность: гомографический решатель с последующим разложением вместо эссенциальной матрицы либо гибрид «вращение из E, длина шага из подобия», давший в первой части работы лучший компромисс. Естественным продолжением является подход Planar-SfM — построение графа поз из гомографических оценок с отбором согласованных рёбер, что для непрерывной траектории полёта применимо напрямую.
- Разделение источников остаточной ошибки направления в {{MEDT_SP}}°: сравнение с эталоном иного происхождения, например с SfM-реконструкцией участка трассы, позволит установить, какая доля приходится на точность телеметрии, какая на калибровку крепления и какая на квазипланарность.
- Априор на вращение от инерциальной системы: при известном R задача сводится к оценке одного направления и становится обусловленной даже при малой базе.
- Оценка разброса от стохастики робастного оценщика: серия прогонов с различными начальными состояниями и доверительные интервалы вместо однократного измерения.
- Перенос протокольного эксперимента на интегральные метрики: чувствительность AUC к порогу оказалась пренебрежимой, тогда как ATE в первой части менялась на 313 %; систематическое сравнение чувствительности двух групп метрик представляет самостоятельный интерес.
- Расширение на полный ALTO и сравнение с плотными матчерами (LoFTR, RoMa), показывающими в опорной публикации лучшие значения AUC и, предположительно, менее чувствительными к бедной текстуре.
