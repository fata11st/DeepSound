## Основные результаты

Три сравниваемых подхода: (a) SIFT + BFMatcher, (b) ORB + Lucas–Kanade,
(c) SuperPoint + LightGlue.

**Задание 1.** Точность траектории и нагрузка на устройство (сплит Val, 4.59 км):

| подход | ATE, м | дрейф, % | мс/пара | кадр/с | VRAM, МБ |
|---|---|---|---|---|---|
| (a) SIFT + Essential | 72.2 | 1.58 | 88.3 | 11.4 | — |
| (b) ORB + Lucas–Kanade | 95.0 | 2.07 | 42.7 | 23.4 | — |
| (c) SuperPoint + LightGlue | 97.4 | 2.13 | 117.3 | 8.6 | 577 |

Наилучший результат по ATE (42.3 м) даёт ORB + Lucas–Kanade с эссенциальной
матрицей и постоянной длиной шага. Разброс результатов по геометрическим
решателям составил 157 % против 5.6 % по фронтендам: определяющим звеном
системы на этом домене является бэкенд, а не фронтенд.

**Задание 2.** Опорная публикация — SURE (arXiv:2603.04869, ICRA 2026),
метрика AUC ошибки относительной позы при порогах 5°, 10°, 20°.
Воспроизведение на ALTO при едином для всех подходов оценщике позы
(сплит Val, база 56.2 м, 300 пар):

| подход | AUC@5 | AUC@10 | AUC@20 | AUC_R@20 | мед. e_R, ° | мед. e_t, ° |
|---|---|---|---|---|---|---|
| (a) SIFT + BF | 29.14 | 64.07 | 81.53 | 96.96 | 0.42 | 3.53 |
| (b) ORB + Lucas–Kanade | 25.97 | 62.77 | 81.22 | 97.76 | 0.30 | 3.64 |
| (c) SuperPoint + LightGlue | **29.22** | **64.61** | **82.31** | 97.34 | 0.51 | 3.52 |
| SP + LightGlue, MegaDepth-1500 (SURE) | 58.80 | 73.60 | 84.10 | — | — | — |

Расхождение с публикацией зависит от порога: при 20° менее двух пунктов,
при 5° около тридцати. Причина — не отказ метода, а систематическое смещение
ошибки направления трансляции на уровне 3.5°, одинаковое для всех трёх
подходов. Суммарная метрика max(e_R, e_t) на этом домене тождественно
совпала со своей трансляционной компонентой, поэтому применять её следует
в раздельной форме AUC_R и AUC_t. Разбор — в `Research_Note.pdf`.

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install numpy scipy pandas matplotlib pyproj psutil reportlab

# OpenCV: строго ветка 4.x и строго contrib-сборка
pip uninstall -y opencv-python opencv-contrib-python opencv-python-headless
pip install "opencv-contrib-python==4.13.0.92"

# обучаемый фронтенд
pip install git+https://github.com/cvg/LightGlue.git
```

OpenCV следует ставить последним: установка LightGlue тянет `opencv-python`
как зависимость и перетирает contrib-сборку, из которой используются
`SIFT_create`, `AKAZE_create` и `logPolar`.

Если пакет `cvg/LightGlue` недоступен, `learned_frontends.py` переключается
на DISK + LightGlue из `kornia` (`pip install kornia kornia_rs`). Это другой
детектор-дескриптор, и ноутбук печатает, какой из путей задействован.

Прогон, результаты которого приложены, выполнен на: Ubuntu в WSL2,
Python 3.12, OpenCV 4.13, PyTorch с CUDA, RTX 2060 (6 ГБ).

## Данные

Каталог с данными задаётся константой `DEFAULT_ROOT` в `src/alto_data.py`
(по умолчанию `/mnt/d/deepsound`) и должен содержать подкаталоги `Train/`,
`Val/`, `Test/`. Ноутбук проверяет его наличие и печатает найденное.

Кадры кэшируются в один `.npy` (`~/alto_cache`, задаётся в ноутбуке).
Кэш обязан лежать на нативной файловой системе: чтение отдельных png через
drvfs даёт около 40 кадров/с и полностью маскирует различия в латентности
фронтендов. Val занимает около 0.4 ГБ, Train около 2.6 ГБ; кэш строится
при первом запуске.

Сплит Test перемешан и лишён телеметрии, поэтому для одометрии непригоден
и в работе не используется.

## Запуск

Каталоги проект определяет сам: ноутбуки ищут корень по наличию
`src/vo_core.py` вверх от рабочего каталога, поэтому запускать их можно
и из `notebooks/`, и из корня проекта.

**Тесты, данные не требуются** (около 30 секунд):

```bash
cd src
python test_pose_auc.py     # метрика и калибровка внешних параметров
python test_vo_core.py      # геометрические соглашения: надирная камера над плоскостью
```

`test_pose_auc.py` проверяет метрику на данных с известным ответом: AUC при
равномерно распределённой ошибке должна дать ровно 0.125 / 0.25 / 0.5,
ошибка вращения для поворота на 3° — ровно 3.000°. Третий блок показывает,
во что превращается метрика без калибровки постоянного разворота камеры.

**Ноутбуки.** Оба выполняются целиком, сверху вниз. Ячейки уже содержат
выводы приложенного прогона. Настраиваемые константы второго ноутбука
собраны в первых двух ячейках: сплит, длина базы, число пар, параметры
робастного оценщика, наборы для развёрток по базе, протоколу и разрешению.

Ориентировочное время второго ноутбука на RTX 2060: около часа целиком,
из них построение кэша несколько минут при первом запуске, развёртка по
базе 8–15 минут, развёртки по протоколу и разрешению 10–20 минут.
При нехватке видеопамяти уменьшите список `RESOLUTIONS`.

Результаты пишутся в `results/` (таблицы, журнал выполнения) и
`report/figures/` (рисунки); приложенный `results/` содержит таблицы первой части. Последняя ячейка пересобирает `Research_Note.pdf`.

**Отчёт отдельно от ноутбука:**

```bash
python src/build_note.py --values report/note_values.json \
                         --template report/research_note.md \
                         --out Research_Note.pdf --figdir report/figures
```

## Корректность прогона

Ноутбук печатает диагностику, по которой видно, что эталонные позы построены
верно. Значения приложенного прогона:

| проверка | ожидание | получено |
|---|---|---|
| надирный тест кватерниона | около −1 | −0.999 |
| согласованность калибровки крепления | > 0.9 | 0.997 на Val и на Train |
| угол эталонного вращения против изменения курса | один порядок | 1.16° против 0.48° |
| отказы оценщика позы | единицы процентов | 0.0 % у всех трёх подходов |
| загруженный обучаемый фронтенд | SuperPoint, не DISK | SuperPoint + LightGlue |

## Особенности окружения

| симптом | причина |
|---|---|
| `AttributeError: module 'cv2' has no attribute 'SIFT_create'` | contrib-сборка перетёрта установкой LightGlue; переустановить OpenCV и перезапустить ядро |
| в выводе DISK вместо SuperPoint | недоступен пакет `cvg/LightGlue`; результаты относятся к другому методу |
| чтение кадров около 40 в секунду | не построен кэш либо он размещён на смонтированном разделе Windows |
| согласованность калибровки ниже 0.9 | мало пар с измеренным сдвигом; при базе в один кадр сдвиг около 5 px и его направление зашумлено |
